# foodId 기반 영양 계산 파이프라인 반영 및 검증 보고서

## 요구사항 매핑

- FR-003: 메트릭 깊이, 기준 평면, 음식 마스크를 이용한 체적 산출
- FR-004: 기준 음식 이미지 임베딩 검색, `foodId` 기반 밀도/영양 조인, 중량 및 영양 계산
- FR-007: 자동 확정 조건을 충족한 분석만 저장

## 반영 내용

1. DINOv2 출력은 음식명 또는 영양 DB가 아니라 라벨된 기준 음식 이미지 임베딩과 비교한다.
2. 카탈로그, 밀도, 영양 데이터를 별도 JSON으로 분리하고 동일한 `foodId` 집합을 강제한다.
3. `weightG = volumeCm3 * densityGCm3`와 기준 중량 비율로 영양소를 계산한다.
4. Top-1 점수 0.80 이상 및 Top-2와 차이 0.10 이상일 때만 자동 확정한다.
5. 후보가 하나뿐이거나 자동 확정 조건을 충족하지 못하면 Top-3를 반환하고 결과를 저장하지 않는다.

## 남은 검증 및 제한

- ArUco API는 현재 OpenCV에 포함되어 있으나, 마커 실제 크기와 검출 코너를 전달하는 API 계약 및 스케일 보정 구현은 아직 없다.
- 운영용 DINOv2 ONNX 모델, 라벨된 기준 이미지 임베딩 인덱스, 출처가 검증된 밀도·영양 데이터가 필요하다.
- 사용자 Top-3 선택을 받아 재계산·저장하는 확정 API와 UI는 아직 구현되지 않았다.
- 기존 DB 스키마는 `foodId`, 분류 신뢰도, 기하 신뢰도를 영구 저장하지 않는다. 컬럼 추가는 마이그레이션 검토가 필요한 고위험 변경이다.
- 공개 Higgsfield 사이트는 UI 검증용 샘플이며 이 로컬 백엔드와 실제 ML 자산이 배포된 서비스는 아니다.
